# Agnes 漫剧工坊 · 本地版

一个本地优先、零云端数据库依赖的 AI 漫剧制作工作台。

它把故事构思、剧情梗概、分集大纲、单集脚本、分镜、图片生成、视频生成、任务轮询和素材管理串成一条本地创作链路。API Key、项目数据和生成记录保存在本机，前端不会直接接触 API Key。

> 本项目使用 [Apache License 2.0](./LICENSE) 发布。

## 功能

- 项目管理：类型、平台、画风、比例、集数和资料导出
- 故事脚本：故事构思、剧情梗概、分集大纲、单集脚本、分镜脚本
- 脚本优化：强化开头、冲突、爽点、反转、钩子、镜头感和精简
- 分镜制作：生成、编辑、排序、批量生成图片/视频提示词，按集生产并自动衔接上下游
- 图片生成：文生图、图生图，本地素材落盘，分镜结果自动回填并可直接进入视频生产
- 视频生成：文生视频、图生视频、多图参考、关键帧动画，继承项目/集数/分镜/素材上下文
- 配音生产：台词与旁白分轨管理，可按镜头关联音频、调用兼容 TTS 服务并只补缺失音轨
- 整集时间线：按分镜顺序自动组装视频、台词和旁白，保留缺失素材提示并支持交接导出
- 任务中心：服务端后台轮询、SSE 实时状态、超时任务补录 video_id
- 素材库：角色/场景/道具资产设定，图片、视频、文本、收藏、预览、下载
- 动态模型目录：从 Agnes 的 OpenAI 兼容 `GET /v1/models` 拉取模型，不需要为新模型改代码
- 数据管理：项目导出、全量 JSON 备份和导入
- 单文件 Windows exe：接收方无需安装 Node.js

## v1.4.0 阶段更新

这一阶段重点是打通并加固「项目 → 剧本 → 分镜 → 资产 → 图片 → 视频 → 配音 → 整集时间线 → 导出」主链路，补齐版本一致性、断点续作与批量生产恢复。

- **多集生产上下文**：单集脚本正式保存 `episode_number`；第 N 集脚本进入分镜时校验项目和集数，避免跨项目、跨集误写。
- **分集大纲驱动下一集**：上一集完成后读取已保存分集大纲，定位真实的下一计划集；进入单集脚本时自动带入该集大纲，不再机械执行 N+1。
- **项目首页继续创作**：按当前集判断单集脚本、分镜、图片、视频、配音、剪辑六个阶段，并直接进入真正缺失的生产环节。
- **分镜生产中枢**：支持只补缺失图片、只补缺失视频、只补缺失配音；生产汇总可直接定位缺失项，并可一键组装整集时间线。
- **资产一致性链路**：增加角色/场景/道具/参考资产实体；支持 `@素材名`、资产提示词展开、主参考图绑定、生成时资产快照，以及图片/视频阶段的参考继承。
- **跨页自动带入**：分镜生成的图片可直接进入视频；项目、集数、分镜和素材上下文在图片、视频、任务、素材库、剪辑台之间持续传递。
- **配音链路**：增加音频素材模型和兼容 TTS Provider；台词与旁白分别检查、分别补齐，整集时间线支持双音轨。
- **剪辑与交接**：按分镜顺序汇总真实视频时长，自动加入视频、台词和旁白；导出清单包含视频轨、台词轨、旁白轨和缺失素材统计。
- **真实媒体校验**：图片、视频、配音 API 返回 `media_readable`；项目首页不再只相信数据库关联，本地文件不存在、为空或记录失效时会回退到对应补齐阶段。
- **任务与失败恢复**：失败任务进入任务中心；对可恢复的视频查询异常优先刷新状态，不自动重复提交，降低重复计费风险。
- **生产版本保护**：图片、视频、对白、旁白按各自版本关联；旧任务迟到完成只保留历史素材，不覆盖当前版本，乱序完成也不会夺回当前关联。
- **剪辑方案重绑定**：保存方案重新打开时按 storyboard 身份绑定最新有效媒体，同时保留人工排序、启用状态、裁切和转场。
- **整集批量生产恢复**：批量队列持久化到本地；应用重启后未完成批次标记为 interrupted 并保留完成现场。
- **重启防重复提交**：恢复已有远端轮询，并兼容从 generation_tasks 的 remote_task_id 恢复在途视频；继续生产时跳过已有远端任务的镜头。
- **OpenReel 简化集成**：保留「打开 OpenReel」和交接清单，不引入复杂 Desktop Bridge；AI 生产留在 Agnes，精剪按需进入 OpenReel。

## 快速开始

### Windows 单文件版

从 [Releases](https://github.com/liobububu/agnes-manga-studio/releases) 下载最新的 `AgnesMangaStudio-vX.Y.Z.exe`（当前 v1.4.0），双击启动。程序会自动打开本地浏览器页面。

> GitHub Release 附件名不支持中文字符，故文件名使用 ASCII。下载后可重命名为 `Agnes漫剧工坊.exe`，不影响使用。

首次使用：

1. 打开「设置 → Agnes API」
2. 填写 Agnes API Base URL 和 API Key
3. 点击「拉取模型目录」同步当前可用模型
4. 在「设置 → 模型配置」选择默认文本、图片和视频模型
5. 新建项目，按脚本 → 分镜 → 图片 → 视频的流程创作

### 源码运行

要求 Node.js 20.6 或更高版本。

```bash
node server.js
```

服务默认监听 `http://127.0.0.1:5178`。也可以指定端口和数据目录：

```bash
PORT=5178 AGNES_STUDIO_HOME=./data node server.js
```

## 数据与安全

- 源码运行时默认数据目录为项目下的 `data/`
- 单文件 exe 默认使用 exe 同级的 `data/`（便携模式）
- `settings.json`、`db.json`、`models.json` 和生成素材不会提交到 Git
- API Key 只由本地服务读取，前端接口只返回脱敏信息
- 本地服务只监听 `127.0.0.1`
- 写操作校验本地 Origin，素材路径做路径穿越防护

## 动态模型目录

程序通过本地服务请求：

```text
GET {API_BASE_URL}/v1/models
```

兼容以下响应格式：

```json
{ "data": [{ "id": "model-name" }] }
```

```json
{ "models": [{ "id": "model-name" }] }
```

```json
[{ "id": "model-name" }]
```

模型目录缓存到本地 `models.json`。默认每 24 小时检查一次；也可以在「设置 → 模型配置」中手动刷新或调整缓存策略。拉取失败时会保留上一次成功的目录和旧模型回退项。

## 图生视频与图床

Agnes 的图生视频只能抓取**公网可访问**的图片，而本地版把图片存在本机。两条路都能走通：

1. **配图床（推荐，全自动）**：「设置 → 图床」选一个免费图床并填 Key（imgbb / SM.MS / 自定义）。
   之后提交图生视频时，本机图片会自动上传并换成公网地址，分镜批量出视频也照常走图生视频。
   同一张图只传一次，公网地址会存回素材记录复用。
2. **手动处理**：「素材库 → 点开图片 → 上传到图床」或手动填「公网访问 URL」。

没配图床时，本地图片会因 Agnes 抓不到而自动降级为文生视频，并提示降级了几个——
不会静默失败，也不会把抓不到的地址硬塞给 Agnes。

图床是可选功能：不配置也能正常用文生视频；只在主动提交图生视频时才上传图片，
Key 只存在本机，不会随项目备份导出。

## 高级参数

视频生成页底部有「高级参数（JSON）」。Agnes 若新增了能力，直接在这里填参数即可用上，
不需要等程序更新；已填的提示词、模型、尺寸等常规参数不会被覆盖。

## 音频生视频

视频生成页有「音频生视频」模式，走的是 **Agnes Video 2.5 的 `audios` 参考**：
填音频的公网直链（最多 3 段），提示词里用 `<Audio 1>` 指代第 1 段，画面会跟着音频节奏走。

两个硬约束（Agnes 侧限制，不是本程序加的）：

- 音频必须是 **公网直链**，总时长 2~12 秒、单段小于 15 MB。本机路径 Agnes 抓不到——
  想用本地音频，需在「设置 → 图床」配置一个支持音频的**自定义**图床（imgbb / SM.MS 只收图片）。
- 只有 **2.5 模型**支持。选了 2.0 模型会直接拦下来并提示换模型，不会发出去白扣一次。

## 剪辑台

「剪辑台」把一集里已经生成好的片段按分镜顺序攒成一条时间线：

- 点「按分镜汇总」自动排队；**没生成视频的镜头会标出来**，不静默跳过
- 每段可设入点/出点、停用、上下移动；段间可设转场（交叉淡化 / 淡入淡出 / 擦除 / 滑动）
- 实时显示总时长；方案可保存、可回载
- 导出「交接清单」：片段顺序 + 入出点 + 转场 + ffmpeg concat 清单

### 为什么不直接导出 OpenReel 工程文件

剪辑台面向 [OpenReel Video](https://github.com/Augani/openreel-video)（MIT，浏览器版剪辑器）。
但 OpenReel 工程文件里的 `MediaItem` 带 `fileHandle`（`FileSystemFileHandle`）和 `blob`，
**这两者都无法序列化成 JSON** —— 也就是说从外部生成的工程文件不可能自带媒体，
打开后仍然要逐个重新关联文件。

所以这里不给「看起来能用、其实打不开媒体」的工程文件，而是导出**真实的片段文件 +
顺序/入出点/转场说明**：把片段放进同一个文件夹，在 OpenReel 里一次性导入即可接着精剪。
